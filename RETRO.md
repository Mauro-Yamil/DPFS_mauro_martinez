# Retrospectiva del Primer Sprint - GreenBite

### 🚀 Comenzar a Hacer (Start Doing)
1. **Estudiar las herramientas antes de comenzar**
2. **Pruebas tempranas**: Implementar testing básico desde el inicio para detectar errores pronto.
4. **Documentar progreso**: Llevar un registro diario de lo desarrollado y los desafíos encontrados.

### 🔁 Continuar Haciendo 
1. **Dividir tareas en componentes**: Buen trabajo separando el proyecto en páginas independientes.
2. **Mantener estructura limpia**: Buen manejo de carpetas y organización de archivos.
3. **Reutilizar componentes**: Buen uso de headers y footers consistentes.

### 💡 Más de
1. **Ejemplos prácticos**: Buscar más ejemplos reales de implementaciones similares.
2. **Revisión de código**: Revisar el código más frecuentemente para mantener calidad.

### 🛑 Menos de
1. **Procrastinación**: Evitar dejar todo para el final del sprint.
2. **Código redundante**: Reducir la repetición de estilos y scripts.
3. **Suposiciones**: Validar siempre los requisitos antes de implementar.

### 🏁 Dejar de Hacer 
 **Saltar la planificación**: No comenzar a codificar sin tener claro el objetivo.

## 📌 Conclusiones Principales

### ✅ Qué salió bien:
- Se logró implementar todas las páginas requeridas
- La estructura del proyecto es clara y organizada
- Se mantuvo consistencia en el diseño

### ❌ Qué salió mal:
- Falta de dominio inicial con las herramientas de desarrollo
- Subestimación del tiempo requerido para ciertas tareas
- Algunos componentes se repitieron innecesariamente

### 🔄 Mejoras para el próximo sprint:
1. **Planificación**: Usar la técnica Pomodoro para mejor gestión del tiempo.
3. **Code reviews**: Revisar el código al final de cada día.
4. **Documentación**: Anotar lecciones aprendidas en cada clase.
